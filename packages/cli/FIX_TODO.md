The required fix was **not** in `tsconfig.json`.

The failure occurs while Turbo is building the backend’s dependency, `@ai-crew-suite/plugin-kernel-node`. Backstage expects this declaration file:

`dist-types/plugins/kernel/node/src/index.d.ts`

But `tsconfig.json` currently inherits the shared `outDir`:

`plugins/kernel/node/dist`

So the needed TypeScript config change is in `tsconfig.json`, adding the Backstage-compatible output directory:

```json
{
  "extends": "../../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "../../../dist-types/plugins/kernel/node"
  },
  "references": []
}
```

The backend config’s reference to `../node` is correct and is not the cause:

```json
{
  "extends": "../../../tsconfig.base.json",
  "references": [
    {
      "path": "../node"
    }
  ]
}
```

There is also a stale incremental-build complication: `tsconfig.tsbuildinfo` can make TypeScript skip declaration emission after `dist` is cleaned. The build cleanup should either remove that metadata or the declaration build should be forced/rebuilt. But the primary path mismatch is the missing `outDir` override in the **node** package config, not the backend config.

Not with the current `crew sync:refs` implementation.

That command reads each `tsconfig.json`, calculates the correct `references`, and writes only this property:

`tsconfigData.references = tsconfigReferences;`

It preserves the existing `compilerOptions`, including:

`"outDir": "../../../dist-types/plugins/kernel/node"`

So adding the `outDir` override to `tsconfig.json` would survive future `yarn sync` and the `sync:refs` step automatically invoked by `crew build`.

Also, `backstage-cli package build` does not rewrite the config. It reads the declaration output produced by TypeScript and then packages it.

The distinction is:

- `yarn sync` → `crew sync:refs` → updates `references` only.
- `crew build` → runs `clean`, `sync:refs`, TypeScript declaration emission, then `backstage-cli package build`.
- `backstage-cli repo fix` → a separate command that may apply Backstage repository conventions.

Therefore, the config fix is stable against the command currently causing the build failure. The only concern would be running `backstage-cli repo fix` separately if it decides that the custom `outDir` is nonstandard. The repository’s own sync command does not remove it.

Not every `tsconfig.json` in the repository needs the same change.

For the immediate failure:

- `backend` depends on `node`.
- The failing package is `kernel/node`.
- Only `tsconfig.json` needs the `dist-types` override to unblock this dependency chain.

The backend config should keep its project reference:

```json
{
  "extends": "../../../tsconfig.base.json",
  "references": [
    {
      "path": "../node"
    }
  ]
}
```

However, the repository-wide scan shows that many other package configs also inherit the shared default:

`"outDir": "${configDir}/dist"`

while their `crew build` command eventually invokes `backstage-cli package build`. Those packages are likely to encounter the same declaration lookup failure when built individually or as dependencies.

So the correct distinction is:

- **Immediate fix:** update only `tsconfig.json`.
- **Broader build-system fix:** add appropriate `dist-types` output paths to every publishable package that uses `crew build`.
- **Do not blindly update every config:** `cli`, for example, intentionally emits to its own `dist/bin`, and frontend/app package output paths have their own Backstage package conventions.

The output paths should follow the package’s Backstage packaging identity, as the existing working configs do. We should not mechanically add the same relative path pattern to every file.
